# db-svc — Микросервис администрирования БД и Хранилища

Синхронный микросервис на базе **FastAPI**, **psycopg 3** и **MinIO S3 (boto3)**, предназначенный для просмотра и редактирования каталога общей PostgreSQL-базы (схемы `core`, `auth`, `chat`, `library`), импорта CSV/датасетов и управления файлами документов в MinIO.

Является инструментом контент-менеджера в экосистеме **«ИИ-помощник студента» (НИУ ВШЭ МИЭМ)**: сам данных не хранит, а администрирует базу, которой питается RAG-чат. db-svc не предоставляет пользовательских функций чата — только служебный CRUD над базой знаний.

---

## Роль в архитектуре системы

db-svc ходит напрямую в общий Postgres и в MinIO — не через другие сервисы экосистемы (`graph-rag-svc`, `chat-svc` и т.д. не задействованы).
Загрузка/скачивание самих файлов идёт по presigned URL напрямую между браузером и MinIO — db-svc лишь выдаёт подписанную ссылку, байты через него не проходят.

---

## Возможности и особенности

- CRUD строк любой таблицы любой схемы: модалка и inline-редактирование, составные первичные ключи, выпадающие списки значений из CHECK-constraint/enum, серверные фильтры и сортировка.
- CSV-импорт в существующую таблицу: построчная вставка (`INSERT` + `SAVEPOINT` на строку, не bulk `COPY`) с отчётом по каждой упавшей строке; колонки матчатся по имени из `HEADER`, порядок не важен.
- Связанный dataset-импорт: 8 CSV-файлов (университеты, кампусы, факультеты, корпуса, программы, темы, документы, document_relations), UUID для новых записей генерируются и связываются автоматически. `dry_run` прогоняет весь импорт в транзакции и откатывает её — то есть проверяются и ограничения БД (NOT NULL, CHECK, UNIQUE, типы), и конфликты с уже лежащими данными; счётчики такого прогона приходят в `would_insert`, а `inserted` остаётся пустым.
- Управление файлами в MinIO: список, presigned upload/download, удаление; импорт файлов с мэтчингом по title к `library.documents`; импорт HTML по `origin_url` с конвертацией HTML → Markdown для RAG.
- Прогресс длительных операций через `/api/jobs/{id}` (создаётся при импорте, поддерживает отмену).
- Bearer-авторизация (`DBSVC_ADMIN_TOKEN`) на всех `/api/*`. Без заданного токена сервис **не запускается**; работать без авторизации можно только с явным `DBSVC_ALLOW_NO_AUTH=true`.
- Строгая валидация идентификаторов схем/таблиц/колонок регэкспом, без ORM — чистый SQL через psycopg.
- Фронтенд — vanilla HTML/CSS/JS (ES-модули), без сборщиков и фреймворков, дизайн по макетам Figma.

## Данные, с которыми работает сервис

В отличие от сервисов-владельцев своих таблиц, db-svc — клиент общей базы `app_db` и своей схемы не имеет (кроме служебной таблицы задач):

- **`core`** — справочники вуза: universities, campuses, faculties, buildings, programs.
- **`auth`** — пользователи и токены (владелец `auth-svc`, здесь только читаются/редактируются вручную).
- **`chat`** — история переписок и фидбек (владелец `chat-svc`).
- **`library`** — база знаний: documents, chunks, chunk_embeddings (`VECTOR(1024)`), document_files, document_relations, contacts, places. Основная зона редактирования через db-svc.
- **`public.dbsvc_jobs`** — служебная таблица самого db-svc для отслеживания прогресса импортов (создаётся автоматически при старте).

Полная схема — `infra/db/init/init.sql` в корне проекта.

## Быстрый запуск

### Вариант 1: через общий docker-compose

```yaml
  db-svc:
    build: ./services/db-svc
    env_file:
      - ./services/db-svc/.env
    environment:
      POSTGRES_HOST: ${POSTGRES_HOST}
      POSTGRES_PORT: ${POSTGRES_PORT}
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_ADMIN_USER}
      POSTGRES_PASSWORD: ${POSTGRES_ADMIN_PASSWORD}
      MINIO_ENDPOINT: ${MINIO_ENDPOINT}
      MINIO_ACCESS_KEY: ${MINIO_ACCESS_KEY}
      MINIO_SECRET_KEY: ${MINIO_SECRET_KEY}
      MINIO_BUCKET: ${MINIO_BUCKET}
      MINIO_REGION: ${MINIO_REGION}
      MINIO_SECURE: ${MINIO_SECURE}
      DBSVC_ADMIN_TOKEN: ${DBSVC_ADMIN_TOKEN}
    ports:
      - "${DBSVC_PUBLIC_PORT}:8000"   # контейнер слушает 8000 (uvicorn)
    depends_on:
      - postgres
      - minio
    restart: unless-stopped
```

```bash
cd pochemuchnic-miem-prj

# Первый раз (поднять зависимости):
docker compose up -d postgres minio

# Собрать и поднять db-svc:
docker compose up -d --build db-svc

# Если кэш мешает (например, после правок в app/static/ всё ещё старый файл):
docker compose build --no-cache db-svc
docker compose up -d db-svc

# Логи:
docker compose logs -f db-svc

# Остановить:
docker compose stop db-svc
docker compose down
docker compose down -v       # со стиранием данных
```

Открыть: `http://localhost:3401` (или другой `DBSVC_PUBLIC_PORT`). Если задан `DBSVC_ADMIN_TOKEN` — вставить его в поле вверху страницы и нажать «Сохранить» (сохранится в `localStorage`).

### Вариант 2: локальный запуск (Python)

Postgres и MinIO должны быть доступны отдельно (например, `docker compose up -d postgres minio` с проброшенными портами).

```bash
cd services/db-svc

python -m venv venv
# Windows: venv\Scripts\activate
# Linux/macOS: source venv/bin/activate

pip install -r requirements.txt

cp .env.example .env   # и поправить хосты/порты под локальный запуск

uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

## Доступ к панели: через `/admin/` за nginx

Панель доступна двумя путями.

**Основной — через nginx, по адресу `/admin/`.** В основном приложении администратору
показывается кнопка «Админка»: она запрашивает у `auth-svc` короткоживущую HttpOnly-куку и
переводит на `/admin/`. Дальше каждый запрос проходит `auth_request` к
`/auth/validate-admin`, и **при отсутствии действующей админ-сессии nginx отвечает сам,
к db-svc не обращаясь** — то есть HTML и JS панели не покидают контур. Не-админ получает
`404`, чтобы не подтверждать существование раздела.

В этом режиме Bearer-токен в браузере не нужен: nginx проставляет `X-User-Role: admin`, и
db-svc принимает его как подтверждение прав (`DBSVC_TRUST_GATEWAY_ROLE`). Это тот же приём,
которым `chat-svc` доверяет `X-User-Id`, и безопасен он ровно до тех пор, пока порт db-svc
не опубликован наружу — иначе заголовок можно подделать, обратившись к контейнеру напрямую.

**Запасной — напрямую с машины**, `http://127.0.0.1:${DBSVC_PUBLIC_PORT}`, с вводом
`DBSVC_ADMIN_TOKEN`. Нужен, если сид-администратор удалён или его пароль сменили и потеряли.

### Администратор по умолчанию

Роль `admin` ставится только в базе, а до базы обычно добираются через саму панель —
замкнутый круг. Поэтому `main/infra/db/init/init.sql` при первой инициализации заводит
пользователя `admin@edu.hse.ru` с паролем `admin`, ролью `admin`, подтверждённым
адресом и строкой профиля (без профиля `GET /users/me` отвечает 404, и кнопка входа в
панель не появится). Логин у него обычный: пароль хешируется тем же bcrypt, который
проверяет auth-svc.

`init.sql` выполняется только на пустом volume. Для базы, поднятой раньше, есть
`main/infra/db/migrations/005_seed_admin.sql` — он делает то же самое и безопасен при
повторном запуске.

Адрес обязан быть на домене `@edu.hse.ru`: фронтенд проверяет домен в `isValidEmail()` ещё до
отправки запроса и на отказ показывает тот же текст, что и на неверный пароль — с любым другим
адресом форма входа просто не обращается к auth-svc, и выглядит это как неправильный пароль.

Пароль по умолчанию рассчитан на локальную разработку. Перед выкладкой наружу его нужно
сменить или удалить этого пользователя — иначе публичный стенд едет с общеизвестной
учётной записью администратора.

Фронтенд панели работает в обоих режимах: все пути строятся **относительно каталога
документа** (`resolveUrl()` в `app/static/js/api/client.js`, относительные `src`/`href` в
`index.html`), поэтому под `/admin/` запросы уходят на `/admin/api/...`, а при прямом
доступе — на `/api/...`.

## Выгрузка данных архивом

На вкладке «Граф» есть две кнопки выгрузки: **граф** (все шесть таблиц схемы `graph`) и
**чанки** (`library.documents`, `library.chunks` и, по флагу, `library.chunk_embeddings`).
Архивы разные, потому что у данных разный жизненный цикл — граф пересобирается, чанки
переиндексируются — и сильно разный объём.

Формат — zip с JSONL по файлу на таблицу и `manifest.json`, где записаны версия схемы, дата,
число строк по таблицам, а для чанков ещё модель эмбеддингов и объявленный тип колонки
(`vector(1024)`). Не `pg_dump` намеренно: выгрузка должна читаться без Postgres и переноситься
между стендами — соседняя команда поднимает свой экземпляр на тех же данных. Векторы
приводятся к тексту (`embedding::text`) и восстанавливаются разбором строки.

Эндпоинты — `GET /api/export/graph` и `GET /api/export/chunks?embeddings=false`. Префикс
отдельный, а не `/api/graph/export`: под `/api/graph/` висит сквозной прокси в graph-rag-svc,
и локальный путь ушёл бы туда.

Обратная загрузка пока не сделана — см. TODO в `services/README.md`.

## Схема `graph`: редактировать через db-svc не следует

В проекте появилась схема `graph` (сущности, алиасы, связи, провенанс), которую наполняет
`graph-rag-svc`. Формально её таблицы доступны через общий CRUD db-svc — **но пользоваться
этим для правки графа не нужно.**

Причины:

1. **Правки не переживут пересборку.** `graph-rag-svc` наполняет граф через upsert по
   естественным ключам, поэтому следующий же прогон построения восстановит сущность, которую
   вручную удалили или склеили. Чтобы правка была устойчивой, она должна выполняться по
   правилам самого сервиса (склейка через алиас, флаг `curated`, стоп-лист) — а не прямым
   UPDATE/DELETE по строкам.
2. **Логика работы с графом живёт в одном месте** — в `app/graph/` сервиса `graph-rag-svc`
   (резолюция сущностей, алиасинг, upsert-правила). Дублировать её здесь на голом SQL значит
   гарантированно разъехаться с билдером.
3. **Владелец графа — соседняя команда**, которая в db-svc не ориентируется.

Курирование графа делается через внутреннее API `/internal/graph/*` самого `graph-rag-svc`
(поиск и карточка сущности, склейка дубликатов, смена `entity_type`, управление алиасами,
отчёт по «сиротам»). Описание — в README сервиса `graph-rag-svc`, раздел 13.3.

**При этом UI курирования графа будет именно здесь** — db-svc является админкой проекта, и
место инструмента контент-менеджера тут. Но реализуется он как **клиент HTTP-API**
`graph-rag-svc`, а не как прямой редактор таблиц `graph.*`.

Что для этого понадобится:

- новый раздел `/api/graph/*` в db-svc, проксирующий запросы в `/internal/graph/*` сервиса
  `graph-rag-svc` (проксирует бэкенд, а не браузер — межсервисные токены не должны попадать
  на фронтенд);
- запись для db-svc в `TRUSTED_SERVICE_TOKENS` сервиса `graph-rag-svc` плюс переменные
  `GRAPH_RAG_URL` / `SERVICE_NAME` / `SERVICE_TOKEN`;
- новый раздел фронтенда `app/static/js/views/graph/` в том же стиле, что `db-explorer/`,
  `import/`, `minio/`: список сущностей с поиском слева, карточка сущности справа, склейка
  выбором двух записей.

Пользоваться этим разделом будет соседняя команда, которой принадлежит граф.

## ⚠️ Технические проблемы и ограничения

Раздел собран аудитом кода — ранее в README он отсутствовал.

### Высокий приоритет

1. ~~**Авторизация выключена по умолчанию.**~~ **Исправлено.**
   `require_auth()` при пустом `DBSVC_ADMIN_TOKEN` просто возвращал управление, то есть
   сервис без настройки был открыт полностью — а открыт он широко: CRUD по любой таблице
   любой схемы (включая `auth.users`), удаление объектов в MinIO, массовые импорты.
   Теперь конфигурация проверяется при запуске (`verify_auth_configuration()` в lifespan):
   без токена сервис не поднимается, а работа без авторизации требует явного
   `DBSVC_ALLOW_NO_AUTH=true` и на каждом старте пишет предупреждение в лог.
   Публикация порта дополнительно ограничена петлевым интерфейсом
   (`127.0.0.1:${DBSVC_PUBLIC_PORT}`), так что снаружи машины админка больше не слушает.

2. **Подключение администраторской ролью.**
   Сервис ходит в БД под `POSTGRES_ADMIN_USER` (владелец схем), то есть никакого принципа
   наименьших привилегий: любая ошибка или обход авторизации означают полный доступ к базе.

3. **Нет журнала действий.**
   Удаление строк, правка `auth.users`, удаление файлов в MinIO и импорты не оставляют следа:
   ни кто, ни когда, ни что именно менял. Для инструмента с такими правами это обязательный
   минимум.

4. **Токен хранится в `localStorage` фронтенда.**
   Любой XSS в админке отдаёт токен с полным доступом к базе. Для инструмента такого уровня
   стоит рассмотреть httpOnly-cookie или хотя бы ограничение времени жизни токена.

### Средний приоритет

5. **Новое соединение с БД на каждый запрос.**
   `get_conn()` вызывает `psycopg.connect(...)` заново и заново перечитывает переменные
   окружения; пула соединений нет.

6. **`ensure_jobs_table()` создаёт таблицу в обход миграций.**
   `public.dbsvc_jobs` появляется при старте сервиса, а не в `main/infra/db/init/init.sql`,
   поэтому схема БД частично живёт вне общего описания.

7. **Валидация идентификаторов отсекает часть допустимых имён.**
   `_IDENTIFIER_RE = ^[A-Za-z_][A-Za-z0-9_]*$` не пропускает идентификаторы с не-ASCII
   символами. Для безопасности это хорошо (значения при этом передаются параметрами, а
   имена дополнительно экранируются `qident()`), но означает, что таблицу с кириллическим
   именем через админку открыть нельзя.

8. **Нет ограничения на объём импорта.**
   CSV и dataset-импорт читают файл целиком; лимита размера и числа строк нет.

### Замечание по конфигурации

9. **`MINIO_PUBLIC_ENDPOINT` должен резолвиться из браузера, а не из контейнера.**
   Ошибка здесь ломает загрузку и скачивание файлов молча — presigned URL выдаётся, но
   браузер не может по нему пройти.
